ОБЩИЕ ТРЕБОВАНИЯ

1. Валюта: все суммы должны отображаться в тенге (₸). Заменить все ₽ на ₸. Пример: 12 500 000 ₸.
2. Форматы сумм: использовать пробелы как разделители тысяч (например, 12 500 000 ₸), без десятичных знаков для целых миллионов.
3. Блокировка действий: навигация всегда активна. Кнопки действий (загрузка, отправка, редактирование) блокируются в соответствии с этапом проекта. Для заблокированных кнопок использовать серый цвет и тултип с пояснением.
4. Информационные баннеры: на всех экранах (кроме дашборда и центра загрузки) должен быть баннер, объясняющий, почему действия недоступны или что нужно сделать для их разблокировки.
5. Состояния кнопок: для всех кнопок действий предусмотреть три состояния: активная (цветная), неактивная (серая, с тултипом), в процессе (с индикатором загрузки — опционально).
6. Даты и время: в блоках активности использовать полные фразы (например, «2 дня назад», «4 дня назад»).

2. ЭКРАН «ЗАГРУЗКА КП» (ВНУТРИ ПРОЕКТА)

Решение: так как есть «Центр загрузки КП», этот экран дублирует функционал. Предлагается:

• Вариант А (рекомендуемый): полностью убрать этот экран, оставить только массовую загрузку в центре.
• Вариант Б (если оставить): сделать зону загрузки компактной (не на пол-экрана), добавить пояснение: «Для массовой загрузки используйте раздел "Центр загрузки КП"». Кнопка загрузки должна быть активна только если проект в статусе «Новый» или «КП не загружено».
 
3. ЭКРАН «ДОГОВОР»

Исправить:

• Кнопка «Перейти к закупкам» должна быть серой (неактивной), пока договор не подписан клиентом. Добавить тултип: «Закупки доступны после подписания договора».
• В блоке «Подписание клиентом» чекбокс «Подписано клиентом» должен быть неактивен (серый), пока договор не сгенерирован. После генерации — становится активным.
• Добавить информационный баннер (уже есть) — оставить как есть.
 
4. ЭКРАН «ЗАКУПКИ»

Уже хорошо:

• Баннер о режиме просмотра до подписания договора.
• Карточки KPI и таблица счетов.
Добавить / исправить:

• В режиме «только просмотр» (до подписания договора) все кнопки действий (например, «Добавить счёт», «Отправить на согласование», «Редактировать») должны быть скрыты или серые.
• В активном режиме (после подписания) должны появляться:
o Кнопка «Добавить счёт» над таблицей.
o В каждой строке счёта со статусом «Черновик» или «Новый» — кнопка «Отправить на согласование».
o Для счетов с отклонением >10% поле «Комментарий ПМ» должно быть обязательным (звёздочка *). Если комментарий не заполнен, кнопка отправки неактивна.
• В столбце «Комментарий ПМ» для строк с отклонением >10% в режиме просмотра отображать либо текст комментария, либо прочерк «—» (если не заполнен). Звёздочку * показывать только в активном режиме.
• Добавить информационный баннер, который меняется в зависимости от статуса:
o До подписания: «Раздел доступен для просмотра. Для создания и согласования счетов подпишите договор с клиентом.»
o После подписания: «Договор подписан. Вы можете создавать счета и отправлять их на согласование.»
 
5. ЭКРАН «СКЛАД»

Исправить:

• Кнопка «Сформировать заявку на отгрузку» должна быть серой (неактивной), пока товары не поступили на склад (статус проекта < «Товары на складе»). Добавить тултип: «Доступно после поступления товаров на склад».
• В режиме просмотра (до поступления товаров) кнопка должна быть серой и некликабельной.
• После поступления товаров кнопка становится активной (синей/зелёной) и при нажатии открывает модальное окно для выбора товаров и количества в резерв.
• В таблице остатков колонка «В резерве» и «Доступно» должны обновляться динамически (в макете можно показать пример с заполненными данными, как сейчас).
• Баннер оставить, но добавить второй вариант для активного состояния: «Товары по проекту поступили на склад. Вы можете сформировать заявку на отгрузку.»
 
6. ЭКРАН «ЗАКРЫВАЮЩИЕ ДОКУМЕНТЫ»

Исправить:

• В режиме «только просмотр» (до отгрузки) зона Drag-and-Drop должна быть затемнена/неактивна (например, серый фон, текст «Загрузка недоступна»). Кнопки «Загрузить» под каждым документом также должны быть серыми и неактивными.
• После отгрузки (когда этап наступил) зона становится активной, кнопки «Загрузить» становятся кликабельными, и ПМ может загружать документы.
• Кнопка «Закрыть проект» (или «Завершить проект») должна быть активна только когда:
1. Все документы загружены (прогресс 4/4).
2. Бухгалтер подтвердил оригиналы (галочка «Бухгалтер подтвердил» активна).
Если не выполнено – кнопка серая с тултипом, поясняющим, чего не хватает (например: «Загрузите все документы (3/4)» или «Дождитесь подтверждения бухгалтера»).
• Добавить второй вариант баннера для активного состояния: «Отгрузка подтверждена. Загрузите все закрывающие документы и дождитесь проверки бухгалтера.»
 
7. ЦЕНТР ЗАГРУЗКИ КП (НОВЫЙ ЭКРАН)

Это ключевой экран. Необходимо добавить:

7.1. Карточки KPI

Оставить как есть: «В очереди», «Обрабатывается», «Готово», «Требует ввода». Добавить пятую карточку: «Ошибка» (количество файлов с ошибкой).

7.2. Фильтры и поиск

Над таблицей добавить:

• Выпадающий фильтр по статусу: Все / Готово / Требует ввода / Ошибка / В очереди / Обрабатывается.
• Поле поиска: Поиск по названию файла или проекту.
• Сортировка по умолчанию: по дате загрузки (новые сверху). Добавить возможность сортировки по статусу, размеру, количеству позиций.
7.3. Массовые действия

• Добавить чекбоксы в первом столбце таблицы для выбора файлов.
• Над таблицей добавить панель массовых действий:
o «Отправить выбранные КП на утверждение» — активна только для файлов со статусом «Готово».
o «Заполнить цены для выбранных» — активна только для файлов со статусом «Требует ввода». При нажатии открывается модальное окно (см. п. 7.4).
o «Удалить выбранные» — с подтверждением.
• Кнопки массовых действий должны быть серыми, если ни один файл не выбран или выбранные файлы не соответствуют условию.
7.4. Модальное окно «Массовое редактирование цен»

При нажатии «Заполнить цены для выбранных» открывается модальное окно с таблицей, содержащей все позиции без цены из выбранных файлов. Структура таблицы:

• Проект (название)
• Наименование товара (из файла)
• Количество
• Поле для ввода цены (пустое, editable)
• Статус (обязательно)
Внизу модального окна кнопки:

• «Сохранить все цены» — отправляет все введённые цены на сервер и закрывает окно.
• «Отмена» — закрывает окно без сохранения.
• Если хотя бы одно поле цены пустое, кнопка сохранения неактивна (серая) с тултипом: «Заполните все поля».
7.5. Таблица файлов

• Добавить колонку «Прогресс» для файлов в статусе «Обрабатывается» (индикатор выполнения, например, полоса загрузки 78%).
• Для файлов со статусом «Ошибка» добавить колонку или иконку с описанием ошибки (при наведении – тултип с текстом ошибки, например, «Не удалось распознать таблицу»).
• В колонке «Проект» для длинных названий использовать многоточие, при наведении – полное название.
• Цветовая индикация статусов:
o «Готово» – зелёный.
o «Требует ввода» – жёлтый/оранжевый.
o «Ошибка» – красный.
o «В очереди» – серый.
o «Обрабатывается» – синий (с анимацией).
7.6. Вкладка «История загрузок»

• Переключение между «Очередь обработки» и «История загрузок (30 дней)» через табы.
• В истории отображать все загруженные файлы за последние 30 дней с фильтрацией по дате, проекту, статусу.
• Добавить возможность скачать файл (иконка загрузки) или удалить из истории (для администратора).
7.7. Информационный блок

Под зоной Drag-and-Drop добавить подсказку: «Файлы обрабатываются в фоновом режиме. Вы можете закрыть страницу – уведомление придёт в колокольчик.»

 
8. ДОПОЛНИТЕЛЬНЫЕ ТРЕБОВАНИЯ КО ВСЕМ ЭКРАНАМ

• Уведомления (колокольчик): в правом верхнем углу отображать количество задач, требующих внимания. При клике – выпадающий список последних 5 уведомлений.
• Все суммы в тенге (₸). Проверить все экраны (дашборд, детали проектов, закупки, договор и т.д.).
• Единообразие баннеров: использовать светлый фон (жёлтый или серый) и иконку информации (ⓘ).
• Тултипы: для всех заблокированных кнопок добавлять пояснение при наведении.
