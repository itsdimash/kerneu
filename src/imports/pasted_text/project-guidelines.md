Общие принципы (важно!)

1. Навигация (боковое или верхнее меню):
o Все пункты (Проекты, Договор, Закупки, Склад, Документы) всегда кликабельны и активны (не делать серыми).
o Пользователь может переключаться между разделами в любой момент, чтобы просматривать данные.
o Активный раздел подсвечивается (как сейчас).
2. Блокировка действий:
o Внутри каждого раздела кнопки, которые изменяют данные или запускают процессы, блокируются (становятся серыми, некликабельными), если текущий этап проекта не позволяет их использовать.
o При наведении на заблокированную кнопку появляется тултип с пояснением, почему она недоступна.
o Все таблицы, списки, реквизиты и прочая информация отображаются всегда (ничего не скрывать).
3. Информационные баннеры:
o В каждом разделе (кроме дашборда) сверху добавить информационный баннер, который поясняет текущий статус доступа к действиям.
o Баннер должен быть ненавязчивым (например, светло-серый или жёлтый фон), с иконкой информации (ⓘ) и кратким текстом.
o Текст баннера зависит от этапа проекта (см. ниже).

2. Экран «КП / Загрузка файла» (самый важный, уже частично переделан)

Логика работы (после загрузки файла):

• Запускается скрипт-парсер, который:
o Извлекает из файла таблицу (наименование, количество).
o Сопоставляет каждую позицию с БД (по точному названию или артикулу).
o Если товар найден – подставляет цену себестоимости.
o Если не найден – ставит цену 0 и подсвечивает строку жёлтым.
• ПМ может вручную редактировать любую цену (клик по ячейке → ввод числа).
• Кнопка «Отправить Комдиру на утверждение» должна быть неактивной (серой), пока есть хотя бы одна строка с ценой = 0.
Что добавить / поправить:

• В таблице «Состав КП» добавить столбец «Статус сопоставления» (или использовать цвет фона строки):
o 🟢 Найдено (цена подставлена) – зелёный фон или иконка.
o 🟡 Найдено в истории закупок – оранжевый фон.
o 🔴 Не найдено (цена = 0) – жёлтый фон, поле цены выделено рамкой.
• Над таблицей добавить чекбокс / переключатель «Показать только позиции без цены» – для быстрой фильтрации.
• Добавить информационный баннер сразу под заголовком:
«После загрузки файла скрипт автоматически подставил цены из базы данных. Позиции без цены (выделены жёлтым) требуют ручного ввода. Отредактируйте цены в таблице, затем нажмите "Отправить Комдиру на утверждение".»
• Кнопка «Отправить Комдиру на утверждение»:
o Состояние 1 (неактивное): серая, текст «Заполните цены для всех позиций».
o Состояние 2 (активное): синяя/зелёная, текст «Отправить Комдиру на утверждение».
• При наведении на неактивную кнопку – тултип: «Есть позиции без цены. Введите цену или удалите позицию».

Что добавить (новый подход):

o Если договор не подписан:
«Раздел "Закупки" доступен только для просмотра. Для создания и согласования счетов необходимо подписать договор с клиентом.»
▪ В этом случае все действующие кнопки (например, «Добавить счёт», «Отправить на согласование») – серые и неактивные.
▪ Таблица со счетами отображается (можно просматривать).
o Если договор подписан:
«Договор подписан. Вы можете создавать счета и отправлять их на согласование.» – все кнопки активны.

• Кнопка «Отправить на согласование» в каждой строке таблицы:
o Активна только если:
▪ Счёт имеет статус «Черновик» (или «Новый»).
▪ Комментарий ПМ заполнен (для строк с отклонением >10%).
o В остальных случаях – серая с тултипом.
• Модальное окно при клике на строку счёта – уже есть в макете (подпись «Нажмите на строку счёта для просмотра деталей»). Оставить как есть.

«Отгрузка подтверждена. Загрузите все закрывающие документы и дождитесь проверки бухгалтера.» – кнопки загрузки активны.

• Кнопка «Завершить проект» – должна быть активной только когда:
1. Все документы загружены (прогресс 4/4).

o Если не выполнено – кнопка серая с тултипом, поясняющим, чего не хватает (например: «Загрузите все документы (3/4)» или «Дождитесь подтверждения бухгалтера»).
 
7. Общее замечание по состояниям кнопок

Для всех кнопок действия (кроме навигационных) используйте три состояния:

1. Активная – синий/зелёный фон, текст, кликабельна.
2. Неактивная – серый фон, текст, некликабельна, при наведении – тултип с причиной.
3. В процессе – с индикатором загрузки (спиннер) – опционально для MVP, но можно не рисовать, просто указать в комментарии.
